# Terrain signed distance

`SignedDistanceField` computes the signed Euclidean distance to the volume represented by a GridMap elevation layer. Each finite sample occupies its complete cell footprint down to negative infinity. Different neighboring heights create exposed vertical step faces. Cell centres and edges follow GridMap coordinates, including translated maps and nonzero circular-buffer start indices.

NaN and positive/negative infinity are unknown cells. Unknown cells and the map exterior are occupied at every height. A query over a known cell includes clearance to those unknown/exterior boundaries. A query over an unknown cell or outside the map throws `std::out_of_range`; a nonfinite query throws `std::invalid_argument`. `isInside()` checks this known-cell query coverage. Geometric boundaries have zero distance. Empty/all-unknown maps are rejected. A failed rebuild preserves the previous field.

`getDistanceAndGradientAt()` returns one distance and its matching gradient in a single traversal. The older distance, interpolated-distance and gradient methods remain available. Both distance methods now evaluate the same continuous geometric function; neither interpolates or extrapolates voxel values. Queries at any finite height are supported. The gradient is the outward unit direction to the nearest boundary, except at true geometric edges or equal-nearest-feature loci where one deterministic feature is selected. There is no artificial grid-sample discontinuity.

Distances are exact for the occupied cell-volume representation, within floating-point arithmetic. This does not certify the elevation map against the physical scene: sensor uncertainty, downsampling, unobserved cell fractions, moving obstacles and swept robot geometry remain the consumer's responsibility. Distance to this volume should not be confused with distance to a bilinearly interpolated elevation surface.

The immutable query data consists of exposed axis-aligned boundary rectangles and a balanced bounding-volume hierarchy. Equal-height runs merge without changing geometry. Construction has no vertical voxel stack; memory depends on horizontal terrain complexity. Query work is pruned by distance bounds but can exceed logarithmic complexity, so benchmark representative maps. Query methods allocate no per-query storage and can run concurrently after construction. Do not rebuild the same object concurrently with queries.

`heightClearance` is finite and nonnegative and affects only `convertToPointCloud()`: export appends samples at known cell centres from the minimum height through the maximum height plus this clearance. Export may create many points and performs actual distance queries; it is a visualization operation, not a prerequisite for control.

Tests compare against independent unions of occupied/free rectangular prisms and analytic ground, step, corner, trench and coverage fixtures. `grid_map_sdf_benchmark` (built with `BUILD_TESTING`) reports build time, P50/P95/P99/max combined-query latency and visited-candidate counts for deterministic 240x240 flat, rough and checkerboard maps. Timing is diagnostic and is not a pass/fail threshold on shared compute.
